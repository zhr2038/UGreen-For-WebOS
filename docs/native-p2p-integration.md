# Native P2P integration contract

Version 0.5.0 integrates native P2P behind explicit Linux/ARM/nonroot service gating. Verified LAN remains first; native starts only without LAN and while a protected foreground lease is active. Unsupported hosts and missing original NAS RSA retain canonical HTTPS fallback without logging out. Original device authorization can be refreshed through normal password/QR login; no conversion from x-rsa-token is allowed.

## Ownership and selection

`createNativeManager({account, enabled:false, prepareSdk, prepareRuntime, acquireActivity})` owns one immutable account copy. `account` contains canonical HTTPS relay origin, alias, token/staticToken/authMode/clientId and the original NAS `nasPublicRsa`. Missing original RSA returns `NAS_PUBLIC_RSA_MISSING` before any SDK start or key discovery. No conversion from password encryption keys or client public keys is supported. SDK identity always uses the original login/scan `token`, independently of HTTP authentication mode. Official Android call-chain analysis traces LoginDeviceResult/ScanLoginDeviceInfo.getToken through the NAS access-token setter into UgAgentP2pConfig and UGAgentConfig.nasToken; static_token is a distinct HTTP credential. HTTP ugk authentication can therefore keep using staticToken without substituting it into SDK identity.

The service supplies these callbacks; none is an HTTP/UI argument:

* `prepareSdk({signal})` calls the existing pinned official SDK provisioner. Proprietary SDK libraries are downloaded to UID-owned private storage and never bundled in Git/IPK.
* `prepareRuntime({sdk,signal})` calls `prepareNativeWorkerRuntime({dir,assetDir,workerDir,sdkDir,runtimeManifest,workerManifest,signal})`. `dir` is the owning state volume's `native-runtime` child; asset/worker directories are the packaged `native-assets` directory. The fixed runtime manifest is `AOSP-RUNTIME-PROVENANCE.json`, and own worker pin is `worker-manifest.json`. Files are hash-checked, canonical UID-owned directory mode0700, normal files0600 and linker/worker0700. Corrupt, symlinked, hardlinked or unexpected files fail closed.
* `acquireActivity({signal,maximumMs})` returns an idempotent release function after a bounded, nonpersistent/nonexplicit Activity is confirmed. It must not relaunch a callback/schedule or override global idle timeout. The application visibility/subscription owns the manager; hide/logout/reset/service quit call its cleanup. Activity completion is invoked once on release; the remote acknowledgment is not exposed as a device acceptance claim. The owning service uses a nonpersistent/nonexplicit Activity and no scheduled callback. A maximum-duration callback revokes the route and prevents transparent respawn under the same exhausted owner.

`await manager.select({signal})` returns either `{client, route, summary, close, retain}` or `{summary}` with a finite reason. Prefer verified LAN first. Invoke native selection only when LAN is unavailable; preserve HTTPS relay when native remains unverified. There is no automatic retry loop. Optional `mediaPath` performs an explicit bounded 4KiB media validation; ordinary connection selection does not read speculative files.

Routes require relay TLS/identity/backend/alias proof, LINK4/5, SDK listen-GOT safety check, own-loopback listener proof, matching unauthenticated NAS handshake and same-socket authenticated alias proof. LINK2 is relay and cannot become P2P. `summary` distinguishes authenticated/verified route from `mediaReadVerified`; metadata does not count as media. WAN remains false. Current becomes false on route change, worker exit, reset or visibility loss.

`NativeNasClient` allows GET/HEAD only, at most four owned concurrent sockets. Every newly opened socket independently verifies unauthenticated NAS identity and same-socket authenticated alias before the requested operation. NAS's existing internal token/ugk query protocol is retained, but no credential-bearing local URL is returned to the UI, route descriptor or log. Only internally recognized raw-media response bytes can update media evidence. Mutations must remain on the existing relay client and must never be blindly retried after an unknown outcome.

`retain()` returns an idempotent snapshot lease release. `releaseOwner()` releases the owning view while active snapshots retain the immutable account. `reset()`/`close()` force-revoke all sockets and child work, including snapshots, for logout/account changes. Never attach a new account to an old manager/client.

## Explicit production limits

Approved limits are maximum 6-hour process wall lifetime, cumulative CPU3600s, AS256MiB, FSIZE0/core0, finite combined stdout/stderr64KiB, selection10s, optional media proof4096B and graceful stop1s then own-child SIGKILL. The C loop and parent wall timer are independently bounded. SDK state output is change-only; duplicate callbacks are suppressed and total frame/output limits still fail closed. UID must be nonroot and match the child process; parent PID is checked before/after parent-death SIGKILL setup. Identity is one stdin frame only. AF_INET/6 only, no AF_UNIX/file-write/process fork-exec/io_uring, loopback-only listening and readonly SDK GOT checks remain. SDK logs are discarded. Diagnostic FPE/divzero observers, stack/register/operand dumps and CPU substitutions are absent.

These ceilings are resource contracts, not a promise of six hours of playback. Throughput, CPU consumption, renewal at lifetime expiry and main-UID/device behavior require separately authorized bounded physical verification. There is no transparent respawn or retry at expiry.

## Offline build and packaging

Run `native/build-worker.sh` from the repository root using an already installed Zig compiler (`CF_ZIG=/absolute/local/zig`). It compiles only; never runs the ARM worker. Then `node tools/audit-native-worker.mjs --record` records binary/source/header hashes. Subsequent `node tools/audit-native-worker.mjs` verifies them, ELF32 ARM PIE interpreter/dependencies/guard exports and absence of diagnostic exports.

`packageNativeAssets(serviceDirectory)` from `tools/package-native-assets.mjs` is an explicit build helper with no import-time copying. It verifies and copies only seven AOSP runtime binaries, NOTICE/provenance, own worker and its manifest. It rejects extra files, including proprietary SDK libraries. The 0.5.0 `package-tv.mjs` explicitly invokes this helper. The package checker verifies every native file/pin/NOTICE and rejects proprietary SDK binaries, runtime credentials and debug probe files. Runtime/worker manifest pins are compiled into the service, rather than trusting mutable JSON pins at execution time.

## Foreground and account scope

The bridge returns a random transport owner scope in each completed home response, alongside the opaque account scope. Connection status reads and visibility posts carry both. Visibility additionally validates bridge generation across asynchronous body reads. An old account, old transport or late request cannot revoke the replacement route merely by retaining the gateway bearer. The app renews a 90-second foreground lease every 30 seconds only while visible/direct-connected/native-enabled; hide/unload sends best-effort false and stops the timer. Missing messages still expire on the service side. Reset/logout/quit closes the manager, and parent-death SIGKILL remains the independent child boundary. UI labels say 原生P2P直连 only for a current authenticated type4/5 route; metadata authentication is distinct from observed raw-media bytes. Main service start requires the exact LS2 sender top.hrhome.nascinema.

For a separately reviewed same-LAN production smoke test, internal AdaptiveNas constructor dependency injection supports preferNative:true; its shipping default remains false. It is never an HTTP/UI option and does not assert WAN traversal.

Automated integration verification: 400 Node tests (391 passed, 9 Windows/POSIX conditional skips, 0 failed), 48/48 browser UI regressions, package checker44 files including11 native assets with no proprietary SDK, native ELF audit passed. Actual main-service execution and the restored shipping package were separately verified on C5 within the bounded acceptance scope above.

Connection capacity uses a distinct finite error: the fifth concurrent read falls back only that request to its captured HTTPS relay. It cannot close the four healthy native sockets or revoke their route. Native transport failures and public status reasons use finite allowlists; arbitrary provider error strings and numeric codes are never promoted to diagnostics.

Capacity fallback also checks the captured transport generation after the relay read resolves or rejects; a late old-account open response is destroyed before AbortError. Native selection uses performance.now for its hard10s deadline, so wall-clock rollback cannot extend it. The internal same-LAN review variant alteration point is service/index.mjs: new AdaptiveNas(config,{nativeFactory,preferNative:true}); default shipping code omits preferNative and remains LAN-first.

Internal preferNative testing also handles initial LAN selection completing before the first scoped foreground pulse: one bounded native attempt is permitted after that pulse, reusing the verified LAN route as fallback. Repeated pulses do not repeat a failed LAN-side preference attempt; shipping preferNative:false remains unchanged.

Protected connection diagnostics preserve nativeReason independently of a healthy LAN main reason/label, and report only finite nativeStage values. Known SDK provision/runtime failures retain static reason codes. lastWorkerFailure is populated only after an unexpected owned-worker close and contains bounded lifecycle booleans/integers plus finite failure/signal enums; it excludes events, SDK JSON, identities, hosts, ports, PIDs and paths. Pending fault cleanup is generation-scoped so an old close cannot overwrite a newer attempt; intentional stop records no new failure snapshot.

Private-state filename validation allows literal plus signs only within an explicit allowlisted filename component, needed by libstdc++.so. Traversal, separators, NUL, roots and unknown names remain rejected. Real Linux Node20.12.2 nonroot filesystem tests copied and verified all seven public AOSP assets plus the own worker twice, including UID/nlink/hash and linker/worker0700 versus library0600, before the deliberate empty-SDK boundary. Linux private-state/runtime tests:19 passed/1 root-only skip; no SDK binaries or native execution were involved.

Relay diagnostics distinguish RELAY_HANDSHAKE, RELAY_BACKEND and RELAY_ALIAS. Each relay GET uses the original bounded3000ms timeout; timeout and known network/TLS error enums survive sanitization into finite NATIVE_RELAY reasons. HTTP error status is limited to100..599; messages, headers, bodies and hostnames are excluded. Certificate verification remains enabled, worker selection remains10s, and no mutation retry was added.

After a foreground pulse, the UI forces one owner-bound connection refresh even inside the normal10s cadence. If an existing check is active, only one follow-up is queued; hidden/unload/cancel/account replacement discard it. Status updates preserve header visibility, scroll and focus. Successful logout immediately clears the old foreground lease and home/check state. Browser regressions cover initial nonprobing relay→pulse→native READY within2s without other APIs, bounded queued refresh and hidden/old-account late pulse isolation.

Caller cancellation is isolated from native integrity failure. An aborted image request returns AbortError/ABORT_ERR, releases only its own slot/agent, does not retry relay and cannot revoke concurrent healthy media/detail requests. Deferred canceled proofs cannot advance authentication; late bodies are cleared and their sockets discarded. Known identity/account/listener/socket/global-route faults remain fatal even when cancellation occurs in the same turn. Cancellation tests cover an active native stream plus canceled image proof and subsequent native detail read.
