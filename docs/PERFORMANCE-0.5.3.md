# v0.5.3 性能与稳定性验证

2026-11-02，比较 v0.5.2 与本版。优先优化实际热点，保留账号隔离、画质事务和资源上限；没有修改 NAS 设置或电视权限。

## 图片取消与队列

旧版客户端切页或离屏后，相册预览仍可能排在服务端队列里继续读取；同一封面的首个 HTTP 请求取消，也可能让后加入的请求失败。本版让每个请求拥有独立订阅：取消最后一个订阅才中止上游，排队但无人使用的任务不再读取或转换。

电视和可选兼容服务共用队列实现，仍限制最多2个本机活动任务、压缩缓存24 MiB；新增128个待处理任务上限、20秒活动任务时限。原生转换不能安全中断时，仍占用其槽位直到结束，不以无限启动新任务替代取消。清理旧代次时，新的订阅不会被旧清理回调删除。

受控 HTTP 测试使用合成 JPEG：先发8个过期请求、取消，再请求新的可见图片，每个上游固定延迟350毫秒。它验证排队和取消效果，不代表所有网络的绝对加载速度。

| 电视端 NativeThumbnails | v0.5.2 | v0.5.3 |
| --- | ---: | ---: |
| 新相册预览等待 | 1750 ms | 374 ms |
| 新封面等待 | 670 ms | 374 ms |
| 相册上游请求数 | 9 | 3（其中2个取消、1个完成） |

可选 Sharp 服务同场景：相册1762→372 ms，封面674→367 ms。新请求不再等待整个旧队列。上游服务器对关闭连接的观察存在传播时间，瞬时计数可包含尚在关闭的请求；本机任务上限仍为2。

复现：`node tools/bench-thumbnails.mjs`。基准不连接真实 NAS。真实 NAS 的配对、列表、图片与导航另外验证。

## C5 导航测量

在同一台 C5、同样119项电影列表中，分别加载旧版和本版。使用 DevTools Input 派发键盘输入，统计按键事件处理时间和显式 JavaScript 布局读取；不是物理遥控器射频延迟或端到端显示延迟。每个场景3个样本取中位数，包含测量包装开销，样本较小且后台图片加载会带来波动。

| 场景 | v0.5.2 中位数 | v0.5.3 中位数 |
| --- | ---: | ---: |
| 列表内部右移 | 14.7 ms | 6.2 ms |
| 列表内部下移 | 11.3 ms | 8.7 ms |
| 导航栏下移 | 4.7 ms | 2.3 ms |
| 海报进入首行 | 7.5 ms | 4.6 ms |
| 横向片单右移 | 4.6 ms | 4.2 ms |

列表内部矩形读取123→0，可见性读取132→2。固定网格优先找相邻项，边缘、弹窗及其他布局保留几何查找；首页跨行从重复排序读取改为线性选择。没有跨按键缓存布局坐标，滚动和窗口尺寸变化仍读取当前布局。

首次取样曾在冷列表尚未返回时超时，未纳入结果。有效样本仍有尖峰：右移旧版8.9–16.6 ms，本版5.0–17.7 ms。因此不能把短测中位数改善写成每次操作都更快或保证固定FPS。

## 网络读取与故障恢复

- 电影首页、列表、详情、搜索，以及相册列表/分类/相册/文件夹/回忆/音乐读取，传递各自 HTTP 请求的取消信号。页面切走时停止本 App 的旧读取；不重放未知写操作，也不保证 NAS 内部查询已经停止计算。
- 缩略图共享、排队取消、最后订阅取消、超时、旧代清理和重入清理补充回归；图片及元数据的端到端 HTTP 取消另有测试。
- 避开浏览器限制的随机本机端口，明确指定的受限端口则报错，普通绑定失败不偷偷换端口。本机Windows动态TCP范围为1024–15000，测试实际遇到过Fetch的`bad port`；规则依据 [Fetch端口限制](https://fetch.spec.whatwg.org/#port-blocking)，没有修改系统动态端口或浏览器安全设置。
- 电影和相册画质在首帧声明后增加短观察期，避免原生解码器随后报错却已提交失败档位。暂停和播放位置仍保留，未知提交结果继续通过活动源核对。

## 实机边界与验证

C5主服务实际报告0.5.3。SDK切换到本App后完成测试并恢复HDMI 1，没有息屏或关机。DevTools键盘179第一次即暂停（0.229秒保持），再次播放推进到0.673秒。实际切到HDMI隐藏取消4K任务，返回同一查看器后重新静默准备；这一项证明恢复启动，没有重复等待完整4K编码完成。

另发现一个明确限制：NAS对240fps高速视频输出的720P/480P转码在C5报解码错误3，虽然同流在桌面Chrome可播放。本版会拒绝这个失败候选、保留原画并继续播放；实际回退1920×1080、时间0.071→0.231、无媒体错误。没有将该样本记成C5转码播放通过，也没有启用未经证实的降帧参数。其他片源能否转码仍按实际编码和设备能力判断。

本地回归：Node440项，431通过、9平台条件跳过；主界面57/57，相册65/65，播放器设置20/20及海报/HEIF/音乐/真实AVC检查。真实NAS接口检查60项：56通过、3空态、1当前样本无外挂字幕；普通用户配对、分页和键盘导航也已执行。

48MP HEIF核心解码算法本次没有更换，不能据此声称其约13秒准备时间显著缩短。公网P2P、长期压力、电视听感、HDR/颜色及物理像素等价仍需独立验收。源图片、用户标题与原始私有测量记录不随仓库或安装包发布。
