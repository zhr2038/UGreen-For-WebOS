# v0.5.0：原生 P2P 接入

- 电视主服务接入原生P2P。默认仍优先受信HTTPS局域网连接；LAN不可用时，在支持的Linux/ARM非root服务环境和有效前台授权下尝试原生路线，失败保留官方HTTPS中继。不把SDK就绪或中继链路误写成P2P成功。
- 首次使用从固定官方来源按需取得约5.4 MB组件并校验，复用本机私有缓存；原始私有SDK不随IPK发布，NAS无需Docker。运行库正确接受C++库文件名中的`+`，仍保留固定清单和完整性检查。
- 旧登录会话若缺少原生连接所需的设备授权，可通过现有密码或扫码入口重新登录一次；不从密码加密握手推导公钥，不强制退出旧账号，HTTPS仍可继续使用。
- 每个读取调用的取消与其他调用隔离，取消海报请求不会自动撤销健康的媒体路线。换账号、退出服务或可见性失效会撤销对应路线并释放自有子进程；只读路线不自动重放结果未知的业务写入。
- 保留0.4.1的透明页头、滚动隐藏/恢复、首页逐行上返海报和播放栏画质入口；异步画质列表就绪后一次性恢复当前档位焦点。

## C5实测范围

主服务UID5567上的原生路线完成认证与媒体读取：HTTP206、4096字节；读取证据由false变为true，页头显示原生P2P。活跃worker一次样本RSS约6864 KiB、11线程，这不是长期资源上限或性能保证。

随后实际UI原画播放达到readyState4、1920×1080，采样时未暂停、未处于定位状态、无媒体错误；位置3931→3931.395秒，确认时钟推进。约2.3秒间隔内观察到上述进度增量，不能据此推断持续速率、长时间或高码率流畅度；本次静音，未新增声音或听感验收。

该同LAN验证使用私有依赖注入，仅改变选路优先级让P2P先于LAN，以验证主UID和实际媒体路径。发布默认仍LAN优先；已重新安装未带私有优先覆盖的原始发布包，实测受信LAN验证成功（ACCOUNT_VERIFY，约1026ms，一次尝试），P2P未被选中、原生能力保持启用，页头显示LAN。透明页头、首页顶部、滚动隐藏/恢复和焦点保持通过。跨网穿透未验，不能用同LAN成功代替WAN验收。

已观察停止本次播放、可见性撤销及静音恢复。独立清理检查曾确认仅主Node进程保留、无残余worker；不将独立探针退出码当作主服务API验收。最新实际播放已确认停止自有播放、撤销可见性和恢复静音；之后退出主服务，再安装默认发布包，旧worker父进程随之结束。没有另行观察该次播放停止后的进程列表，不将此前清理检查移作该次观测。
